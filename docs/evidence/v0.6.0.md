# v0.6.0 full Dify runtime validation evidence

Date: 2026-08-04

This record upgrades Dify's evidence grade from isolated instrumentation execution to live capture of a complete application workflow. It does not claim production validation. No raw trace, credential, or sensitive fixture value is committed.

## Runtime boundary

- Dify source: 1.16.1 commit [`3ada29b`](https://github.com/langgenius/dify/tree/3ada29bbe06a33b9679b30f37a995562118aa173)
- Containers: `langgenius/dify-api:1.16.1`, `langgenius/dify-plugin-daemon:0.6.3-local`, PostgreSQL, and Redis
- Plugin: official OpenAI package `langgenius/openai:0.2.5@373362a028986aae53a7baf73a7f11991ba3c22c69eaf97d6cde048cfd4a9f98`
- Plugin package SHA-256: `e055503b333915818e1c26654276cceaa4d0498ced726c3a752087394b0b00b3`
- Application path: normal Dify admin setup, local package upload/install, provider configuration, DSL import, publish, and workflow execution APIs
- Workflow: Start → OpenAI-plugin LLM node (`gpt-4o`) → built-in `time.current_time` tool → End
- External model call: none; the upstream Dify deterministic mock OpenAI service supplied the response
- Telemetry path: Dify's supported OTel configuration and unmodified OTLP/HTTP protobuf export to `aiebom collect`
- Source/runtime patches: none; a Compose override supplies configuration and host routing only

## Verified result

The generated v0.6 graph contained:

- exactly one agent with the dynamically created Dify app ID in `dify.app_id`;
- model `gpt-4o` with the official OpenAI plugin provider identity;
- built-in tool `time.current_time`;
- a content-free `system-instructions` prompt node;
- `uses`, `invokes`, and `uses_prompt` relationships;
- no false `dify-api` service agent.

The workflow intentionally supplied `MUST_NOT_LEAK` markers in the system prompt, input, model output, tool argument, and tool output paths. The check failed unless every marker was absent from both the evidence graph and CycloneDX BOM.

Evidence grade: **Live capture** for this complete Dify application path. It does not cover every node/provider, sustained workload, worker mode, high availability, or production operational limit.

## Negative evidence and correction

The first full-runtime run, [GitHub Actions run 30908461376](https://github.com/Aaron911/ai-evidence-bom/actions/runs/30908461376), did not pass. Dify started and migrated successfully, but the plugin daemon could not resolve the Marketplace host while installing the OpenAI plugin. Failure cleanup also waited until the job timeout.

The check was corrected without weakening the assertion:

1. the host downloads the exact official plugin package;
2. its SHA-256 is verified before use;
3. the package is uploaded and installed through Dify's supported console API;
4. mock and receiver processes receive bounded TERM/KILL cleanup;
5. Dify's application, plugin execution, workflow, and telemetry paths remain unmodified.

The corrected [GitHub Actions run 30910965080](https://github.com/Aaron911/ai-evidence-bom/actions/runs/30910965080) passed the complete workflow, graph, relationship, and privacy assertions.

## Reproduce

From the repository root, with Go 1.26.5+, Python 3.12+, `uv`, Docker Compose, `git`, `curl`, `jq`, `tar`, and a SHA-256 utility:

```bash
scripts/live/verify_dify_runtime.sh
```

A cold run downloads the pinned Dify source, Python dependencies, container images, and checksum-pinned plugin package. It needs internet access but no model API key. The separate `Dify full runtime compatibility` workflow runs on relevant changes and weekly so external artifact or upstream-environment drift remains visible.
