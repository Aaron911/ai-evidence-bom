# v0.5.0 framework validation evidence

Date: 2026-08-04

This record distinguishes a complete core-runtime capture from isolated execution of framework instrumentation. No raw trace or sensitive fixture value is committed.

## Microsoft Agent Framework — live capture

- Package: `agent-framework-core==1.13.0`
- Exporter: `opentelemetry-exporter-otlp-proto-http==1.43.0`
- Path executed: released `Agent`, `ChatTelemetryLayer`, `FunctionInvocationLayer`, deterministic `BaseChatClient`, real tool execution, and OTLP/HTTP protobuf export
- External model call: none; the deterministic chat client avoids credentials, cost, and network-dependent model behavior
- Verified graph: one stable agent, OpenAI `gpt-5`, `weather.lookup`, a content-free prompt node, and `uses`, `invokes`, and `uses_prompt` relationships
- Privacy assertion: system instructions, agent input, model output, tool arguments, and tool results containing `MUST_NOT_LEAK` did not appear in graph or BOM output

Evidence grade: **Live capture** for the released core runtime path. This is not production validation and does not cover every provider integration or multi-agent handoff.

## Dify — instrumentation execution

- Source: Dify 1.16.1 commit [`3ada29b`](https://github.com/langgenius/dify/tree/3ada29bbe06a33b9679b30f37a995562118aa173)
- Exporter: `opentelemetry-exporter-otlp-proto-http==1.44.0`
- Path executed: real `WorkflowAppRunnerHandler`, `LLMNodeOTelParser`, and `ToolNodeOTelParser` loaded from the pinned checkout, followed by OTLP/HTTP protobuf export
- Host boundary: surrounding Dify application and Graphon domain objects are deterministic stubs; no API server, worker, database, Redis, or complete workflow runtime was started
- Verified graph and privacy assertions: the same core identities, relationships, and sensitive-marker exclusions as the Microsoft check

Evidence grade: **Instrumentation execution**. This is stronger than a source fixture but does not qualify as Dify live capture.

## Defect found by live execution

The Dify check initially exported child spans before their parent. The receiver normalized each request separately and temporarily attributed model/tool spans to `service.name`, creating a false `dify-api` agent. v0.5 adds bounded cross-request trace context:

1. unresolved children retain only allowlisted metadata;
2. parent identity releases queued descendants recursively;
3. prompt bodies, messages, and tool arguments/results are removed before queuing;
4. pending items and trace contexts are bounded by `--max-dedupe-items`;
5. child-first behavior is protected by a regression test.

## Reproduce

From the repository root, with Go 1.26.5+, Python 3.12+, `uv`, `git`, `curl`, and `jq`:

```bash
scripts/live/verify_agent_framework.sh
scripts/live/verify_dify_instrumentation.sh
```

Cold runs download pinned packages and, for Dify, a sparse pinned source checkout. Neither check needs a model API key.
