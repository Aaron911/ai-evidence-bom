# v0.7.0 MCP runtime identity and capability-drift evidence

Date: 2026-08-05

This record tests whether one real MCP client/server tool call can produce stable, non-content-derived server identity and whether an uninvoked capability addition can be detected through graph diff and a directed path policy. It does not claim production validation, automatic SDK telemetry, or trust in server declarations.

## Pinned boundary

- Official MCP Go SDK: [`v1.7.0`](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.7.0), commit [`bc72835f62eb94d0fb484439f886b6885b075f36`](https://github.com/modelcontextprotocol/go-sdk/tree/bc72835f62eb94d0fb484439f886b6885b075f36)
- SDK module zip SHA-256: `324a2a6956be6b4aa8a92057cf2ac71ad91bdbbf4dd3d9a00a192e789843a320`
- MCP protocol negotiated by the runtime: `2026-07-28`
- OpenTelemetry Go API/SDK/exporter: `v1.44.0`
- OpenTelemetry GenAI MCP convention reviewed at commit [`7e6e1884b242a277e6e2494e698f69481fe6fea8`](https://github.com/open-telemetry/semantic-conventions-genai/tree/7e6e1884b242a277e6e2494e698f69481fe6fea8)
- Transport: official `CommandTransport` client spawning an official `StdioTransport` server
- Model call and credential: none

## Runtime sequence

The deterministic client executes:

1. `server/discover` and requires `serverInfo.name=demo-security-tools`, version `1.0.0`, and protocol `2026-07-28`;
2. `tools/list` and converts the content-free capability identity into declared evidence;
3. `tools/call` for `weather.lookup` with application OTel instrumentation around the real SDK call;
4. OTLP/HTTP protobuf export into `aiebom collect`;
5. the same sequence against a changed server that additionally declares `shell.execute` but never calls it.

The official SDK does not contain built-in OTel emission. The live check uses its public middleware boundary after protocol discovery. Actual list/call spans use standard `mcp.method.name`, `mcp.protocol.version`, `network.transport=pipe`, `gen_ai.operation.name`, and `gen_ai.tool.name` attributes. Because the reviewed OTel convention has no stable logical server-name attribute, protocol `serverInfo` is carried by the explicitly project-owned `aiebom.mcp.server.*` bridge.

## Verified result

The baseline graph contains exactly one Agent, one MCP server, and `weather.lookup`. The changed graph additionally contains `shell.execute` with `declared` evidence.

- `weather.lookup` becomes `observed` because `tools/call` executed it.
- `shell.execute` remains `declared`; no `agent -[invokes]-> shell.execute` edge is invented.
- Server identity is stable across baseline and changed graphs and comes from `serverInfo`, not description, arguments, results, executable path, or network-content guessing.
- Diff reports one added tool node and one added `mcp_server -[provides]-> tool` edge.
- The baseline passes [`policy-mcp-capability.json`](../../examples/policy-mcp-capability.json).
- The changed graph exits 3 with the matched path `agent -[connects_to]-> mcp_server -[provides]-> shell.execute`.

Evidence grade: **Live capture** for this client-side stdio path, with protocol identity and declared capability evidence. Server-side spans and cross-process OTel propagation are not validated.

## Privacy assertion

The server places distinct `MUST_NOT_LEAK` markers in tool descriptions, generated input schemas, call arguments, and call results. The check fails if any marker reaches the evidence graph, diff, policy report, or CycloneDX output. Raw schemas are discarded; only an input-schema SHA-256 is retained for drift detection. MCP annotation hints are labeled untrusted.

## Negative evidence and standards gap

- The official SDK does not automatically produce OTLP; self-developed clients still require SDK, framework, or application instrumentation.
- The reviewed OTel MCP convention is Development status and defines no stable logical MCP server identity.
- Its method registry and lifecycle examples still include the legacy `initialize`/list-changed model, while the tested MCP `2026-07-28` runtime uses `server/discover`, per-request metadata, and `subscriptions/listen`.
- Therefore v0.7 does not call legacy `mcp.server.*` aliases standard and does not claim universal MCP auto-instrumentation.

## Reproduce

From the repository root, with Go 1.26.5+, `curl`, and `jq`:

```bash
scripts/live/verify_mcp_runtime.sh
```

The check builds the repository and pinned modules, starts two loopback-only collectors, executes both real MCP subprocess sequences, and removes its temporary artifacts. A cold module cache needs network access; no model API key or paid service is used.
